# Chunk palette shape drift (DataVersion 5023+)

## Goal

Savegame `01` (a newly created world) fails to load: `ranvil-cli ... column`
against it reported `unexpected NBT type for field: block_states.palette`,
and `world::decode_chunk` (the viewer's real load path, via `ChunkRegion`)
would hit the same error on any chunk generated by the newer game build.

## Root cause

Checked the raw NBT of `01`'s region files (all 9 regions, 4323 chunks) by
hand. `01` is `DataVersion` 5023 — newer than the 4438 build `ranvil` was
last verified against (see `ChunkRegion::mark_for_relight`'s doc comment).
That build writes `block_states.palette` entries in one of three more
compact shapes instead of the old `{Name, Properties?}` compound:

- a bare `TAG_STRING` (just the block id) when the block has no properties
- a `TAG_COMPOUND` with a single *unnamed* string field, same no-properties
  case
- a `TAG_COMPOUND` with fields named lowercase `id` / `properties` when the
  block has properties (property keys inside `properties` stay named, e.g.
  `facing`/`axis` — only the two fixed outer roles lost their names)

A chunk the old build wrote and one the new build generated later can sit in
the same region file (chunks aren't rewritten just because the game
updated) — `01` has both, so this had to be handled per section, not assumed
for the whole save.

## Fix

`ranvil`'s `ChunkRegion::load_chunks` now normalizes every section's
`block_states.palette` back into the legacy `{Name, Properties?}` shape
right after parsing (`normalize_palettes` in `chunkregion.rs`), before
anything else in the crate — or in `block_viewer` (`world::decode_chunk`,
`viewer::paint`, `city::commit`/`demolish`/`save`, ...) — reads it. Every one
of those goes through `ChunkRegion::get_chunk`, so none of them needed their
own changes.

Writes are untouched: `edit_section` still writes the legacy shape, which is
already the crate's established migration policy (same as the
`dimensions/minecraft/overworld` region-folder move) — a newer game build
keeps reading a save's older layout rather than requiring a rewrite.

Structure files (`blueprint`'s `.nbt` export/import) are a separate format
and unaffected — out of scope here.

    depends on whatever real `.minecraft/saves` regions happen to exist on
    the machine having a fully-generated centre chunk — inherently
    environment-fragile, already flagged as such in its own doc comment.
  - `city::road_build::tests::removing_that_building_reverts_the_cell_to_surface`
    and `...two_buildings_bordering_one_cell_keep_it_connected_when_one_goes`
    fail in isolation with "AsyncComputeTaskPool has not been initialized" —
    a Bevy test-ordering issue unrelated to NBT/anvil parsing.
